## 1. Python packages in the desktop app

The runtime dependency closure of `hey-spark` with the `desktop`, `oww` and `kokoro` extras, on Windows. It is
generated by `scripts/third_party_notices.py`; re-run it after changing dependencies:

```bash
uv run python scripts/third_party_notices.py
```

Notes:

- **macOS build.** The macOS app has the same closure minus the Windows-only packages (`pywin32`,
  `pythonnet`, `clr_loader`, `colorama`), plus pywebview's Cocoa bridge: `pyobjc-core`,
  `pyobjc-framework-Cocoa`, `-Quartz`, `-Security`, `-UniformTypeIdentifiers` and `-WebKit`
  (12.2.2, MIT, https://github.com/ronaldoussoren/pyobjc). PyAV's macOS wheel bundles the same
  FFmpeg libraries as `.dylib` files, with the same terms as on Windows.
- `pvporcupine` is a runtime dependency of the source install, but the PyInstaller build excludes it
  (`packaging/hey_spark.spec`). If you use it, the Picovoice terms of your AccessKey also apply.
  Optional backends that are never in the frozen app (`deepgram-sdk`, `elevenlabs`) are not listed.
- **piper-tts is GPL-3.0-or-later** (project `OHF-Voice/piper1-gpl`). It embeds espeak-ng
  (GPL-3.0-or-later, https://github.com/espeak-ng/espeak-ng) through `piper/espeakbridge.pyd` and
  ships `espeak-ng-data`. The frozen Windows app bundles both, so when you distribute it you must
  meet GPL-3.0 terms for that build: give recipients the license text and the corresponding source
  (or a written offer for it); see section 5. The Hey Spark code is MIT, which is GPL-compatible, and its source is
  public. piper-tts also includes g2pW code under Apache-2.0 and Hebrew code under the MIT license.
- **Kokoro voices.** `kokoro-onnx` (MIT) reads text through `phonemizer` (GPL-3.0-or-later)
  and espeak-ng 1.52.0 (GPL-3.0-or-later), whose library and `espeak-ng-data` ship inside
  `espeakng-loader` (MIT wrapper; its wheel metadata states no license, the repository's

- `certifi` (MPL-2.0) and `tqdm` (MPL-2.0 AND MIT) are file-level copyleft: unmodified files may be
  shipped as-is, with the license, and the source is available from the linked projects.
- `av` (PyAV, BSD-3-Clause, pulled in by faster-whisper) bundles FFmpeg DLLs in `av.libs`. FFmpeg

  `pywin32` and `pythonnet` contain native libraries with their own bundled notices. See each

## 3. Claude Code CLI (not bundled)

The `claude-agent-sdk` wheel (0.2.159) ships the Claude Code CLI binary
(`claude_agent_sdk/_bundled/claude.exe`, CLI version 2.1.281). The frozen app **leaves it out**
(`packaging/hey_spark.spec`) and uses the Claude Code you install yourself (found on `PATH`, in
`~/.local/bin`, or at `brain.cli_path`). A source install gets the binary from PyPI with the SDK,
as Anthropic distributes it.

- The package's only license file, `claude_agent_sdk-0.2.159.dist-info/licenses/LICENSE`, is the MIT
  License, Copyright (c) 2025 Anthropic, PBC. Its metadata says `License: MIT`.
- The package README ("License and terms") says use of the SDK is governed by Anthropic's
  Commercial Terms of Service (https://www.anthropic.com/legal/commercial-terms), "except to the
  extent a specific component or dependency is covered by a different license as indicated in that
  component's LICENSE file".
- The wheel has no separate LICENSE file for the bundled `claude.exe`. The Claude Code project's
  own license (https://github.com/anthropics/claude-code/blob/main/LICENSE.md) reads:
  "© Anthropic PBC. All rights reserved. Use is subject to Anthropic's Commercial Terms of Service."

So the CLI binary is proprietary Anthropic software, not open source, and not covered by Hey Spark's
MIT license. Hey Spark's Claude brain uses it with your own Anthropic API key
(`ANTHROPIC_API_KEY`), under Anthropic's terms.
